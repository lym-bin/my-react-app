# Objet & B

절제된 실루엣과 미니멀한 디테일을 콘셉트로 한 쇼핑몰 웹사이트입니다.
상품 목록/상세, 장바구니, 주문·결제, 로그인/회원관리까지 실제 이커머스 서비스에 필요한 기능들을 처음부터 끝까지 직접 구현해봤습니다.

배포: https://my-react-app-lym-bin.vercel.app/

## 사용 기술

- React 19 + TypeScript
- Vite
- Tailwind CSS v4 (`@theme` 디자인 토큰)
- GSAP (스크롤 애니메이션, 인트로 모션)
- React Router
- Firebase (Authentication, Firestore)
- 토스페이먼츠 결제 SDK (테스트 모드)
- Vercel Functions (결제 승인 API)
- lucide-react

## 기능

- 상품 목록 카테고리/색상/사이즈 필터링, 정렬, 더보기 페이지네이션, 검색
- 상품 상세 페이지 - 색상/사이즈 옵션, 사이즈 가이드, 비슷한 상품/스타일링 컷 추천
- 장바구니 (옵션별 개별 관리, 수량 조절, 새로고침해도 유지)
  - 계정마다 따로 저장, 로그인하면 비로그인 상태에서 담아둔 상품을 합쳐줌
- 배송지 등록/선택 (Firestore에 계정별 저장)
- 토스페이먼츠 테스트 결제 (실제 출금 없음)
  - 결제창 → 서버(Vercel 함수)에서 금액을 다시 계산해 검증 → 결제 승인 → 주문 저장(Firestore) → 장바구니 비우기
  - 시크릿 키는 서버에서만 사용하고, 이미 승인된 결제를 다시 요청해도 같은 결과가 나오도록 처리
- 이메일/비밀번호 로그인, 회원가입, 비밀번호 재설정
- 마이페이지 - 주문내역 조회, 최근 본 상품, 닉네임/비밀번호 수정
- 브랜드 스토리 페이지 (GSAP 핀 고정 + 가로 스크롤)
- 첫 방문 인트로, 반응형 다크테마 UI, GSAP 스크롤 애니메이션

## 데이터 구조

| 데이터 | 저장 위치 | 이유 |
|---|---|---|
| 상품 | 코드 안의 로컬 데이터 (`ProductsData.ts`) | 자주 바뀌지 않는 포트폴리오 범위라 API 없이 관리 |
| 주문 | Firestore `orders` | 사용자별로 저장·조회해야 함 (결제 승인 후 저장, `paymentKey` 포함) |
| 결제 중인 주문 | sessionStorage | 결제창에 다녀오는 동안만 필요한 임시 데이터, 탭마다 따로 |
| 배송지 | Firestore `users/{uid}/addresses` | 이름·전화번호가 들어가서 브라우저가 아닌 계정에 저장 |
| 장바구니 | localStorage (`objet-b-cart-{uid}`) | 결제 전 임시 데이터, 계정별 키로 분리 |
| 최근 본 상품 | localStorage | 이 브라우저에서만 의미 있는 기록 |

Firestore 보안 규칙으로 **본인 uid의 데이터만** 읽고 쓸 수 있게 막았고, 배송지는 정해진 항목과 글자 수만 저장되도록 제한했습니다.

## 실행 방법

먼저 패키지 설치:

```bash
npm install
```

개발 서버 실행 (localhost:5173, 화면만):

```bash
npm run dev
```

결제까지 테스트하려면 서버 함수(`api/`)도 같이 띄워야 해서 Vercel CLI로 실행합니다 (localhost:3000). 프로젝트 최상위에 `.env`가 필요합니다. 키는 [토스페이먼츠 개발자센터](https://developers.tosspayments.com)의 API 개별 연동 **테스트** 키를 사용합니다.

```bash
# .env (git에 올리지 않음)
VITE_TOSS_CLIENT_KEY=test_ck_...   # 브라우저용, 공개돼도 되는 키
TOSS_SECRET_KEY=test_sk_...        # 서버 전용, VITE_ 접두사를 붙이지 않음
```

```bash
npm i -g vercel
vercel link
vercel dev
```

타입 검사 / 빌드:

```bash
npm run typecheck
npm run build
```

## 개선 기록

배포 후 피드백을 받고 고친 내용들입니다. 2026년 10월부터는 브랜치를 만들고 PR을 거쳐 머지하는 방식으로 작업했습니다.

**성능 / 구조**
- 이미지를 WebP로 변환하고 쓰지 않는 이미지를 정리해서 이미지 용량을 **28MB → 2.8MB**로 줄였습니다.
- 픽셀로 흩어져 있던 글자 크기와 콘텐츠 폭을 Tailwind `@theme` 토큰(rem)으로 정리했습니다.
- 레이아웃과 각 페이지에 `<main>`이 중복으로 들어가 있던 구조를 페이지당 하나로 정리했습니다.

**기능**
- 장바구니가 한 브라우저의 모든 계정에서 공유되던 문제 → 계정별 키로 분리했습니다. 로그인/로그아웃으로 키가 바뀌는 순간 이전 목록이 새 키에 저장되지 않도록 "지금 목록이 어느 키에서 왔는지"를 따로 기억합니다.
- 배송지(이름·전화번호)를 localStorage에서 Firestore로 옮기고 보안 규칙을 추가했습니다.
- 버튼만 있던 결제를 토스페이먼츠 테스트 결제로 실제 연동했습니다. 브라우저가 보낸 금액은 믿지 않고 서버가 상품 데이터로 다시 계산해서, 다르면 승인 요청 전에 거절합니다.
- 마이페이지 주문내역이 무작위 순서로 나오던 문제를 최신순 정렬로 고쳤습니다.

**버그 수정**
- 첫 방문 때만 인트로 모델 사진이 오른쪽으로 치우치던 문제: 이미지가 로드되기 전 GSAP이 Tailwind의 `translate`를 0px 기준 값으로 고정해버린 것이 원인이었습니다. 가운데 정렬은 감싸는 요소가, 애니메이션은 이미지가 맡도록 역할을 나눠 해결했습니다.
- 큰 화면에서 홈 상품 목록 애니메이션이 인트로에 가려진 채 재생되던 문제: 인트로가 끝난 뒤에만 애니메이션을 준비하도록 바꿨습니다.
- 메인 배너에서 스크롤 효과(GSAP)와 마우스 호버 확대(CSS)가 같은 요소의 `transform`을 서로 덮어쓰던 문제를 요소를 나눠 해결했습니다.
- 사진 속에 다른 브랜드 로고가 찍혀 있던 이미지들을 찾아 교체/삭제했습니다.

**디자인**
- 피드백을 반영해 마우스를 따라다니는 배너 뱃지를 없애고, 스크롤 안내를 눈에 띄는 원형 버튼으로 바꿨습니다.
- 인트로 사진을 어둡게 가라앉히지 않고 원래 색감을 살린 고해상도 정면 사진으로 교체했습니다.
- 데스크톱(1920px)에서 상품 목록 빈칸, 화면 끝에 붙어 있던 슬라이드 화살표, 헤더와 맞지 않던 푸터 폭을 정리했습니다.

## 트러블슈팅

토스페이먼츠 결제 승인을 Vercel 서버 함수(`api/confirm.ts`)로 붙이면서, 코드보다 **개발 환경 설정**에서 시간을 가장 많이 썼습니다.

**1. `vercel dev`로 띄운 localhost:3000이 백지로 나옴**
- 증상: 서버 함수를 같이 실행하려고 `npm run dev` 대신 `vercel dev`를 쓰자 화면이 아무것도 안 그려졌습니다. 배포 사이트는 멀쩡했습니다.
- 원인: SPA 새로고침을 위해 `vercel.json`에 넣어 둔 `"source": "/(.*)" → /index.html` 규칙이 **모든 주소**를 가로챘습니다. 개발 서버에서는 `/src/main.tsx`, `/@vite/client` 같은 스크립트 요청까지 HTML이 돌아와서 앱이 실행되지 않았습니다. 배포 환경에서는 실제 파일이 규칙보다 먼저 처리돼서 드러나지 않았던 문제였습니다.
- 해결: 규칙을 **페이지 주소에만** 적용되도록 `"/((?!api/|@)[^.]*)"`로 좁혔습니다. 점(.)이 있는 파일 요청, `api/`(서버 함수), `@`(Vite 개발 도구)는 제외됩니다.

**2. `@types/node`를 설치했는데도 `Cannot find name 'process'`**
- 원인: 이 프로젝트의 TypeScript 7은 `node_modules/@types`를 자동으로 불러오지 않고, 쓸 타입을 `types`에 직접 적어야 합니다. 또 루트 `tsconfig.json`은 `src/`만 포함하고 있어 `api/` 폴더가 관리 대상이 아니었습니다.
- 해결: `api/tsconfig.json`을 따로 만들어 `"types": ["node"]`를 지정했습니다. 루트 설정에 넣지 않은 이유는 브라우저 코드(`src/`)에서 `process`를 실수로 써도 타입 검사가 잡아내게 하려는 것입니다. `npm run typecheck`가 `src/`와 `api/`를 둘 다 검사하도록 바꿨습니다.

**3. 로컬에서는 되는데 배포하면 깨질 뻔한 import**
- 원인: 파일 이름은 `pendingOrder.ts`인데 import는 `./PendingOrder`였습니다. Windows는 대소문자를 구분하지 않아 로컬에서는 동작했지만, Vercel 서버(Linux)는 구분해서 빌드가 실패했을 상황입니다.
- 해결: 타입 검사(TS1261)가 배포 전에 잡아줬고, import를 실제 파일 이름과 맞췄습니다.

**4. 서버 함수가 시크릿 키를 읽지 못함**
- 원인: Vercel 대시보드에 `Secret` 타입으로 등록한 환경변수는 보안상 로컬 개발(Development) 환경으로 내려오지 않았습니다.
- 해결: 로컬에서는 git이 무시하는 `.env`에 `TOSS_SECRET_KEY`를 따로 넣었습니다. 이름에 `VITE_`를 붙이지 않아 브라우저 코드에는 포함되지 않습니다.

**5. 로컬에서는 되는데 배포한 서버 함수만 500 (`FUNCTION_INVOCATION_FAILED`)**
- 증상: `vercel dev`에서는 결제 승인이 잘 됐는데, Vercel 미리보기 배포에서는 `/api/confirm`이 모든 요청에 500을 냈습니다.
- 원인: Vercel 로그에 `ERR_MODULE_NOT_FOUND: Cannot find module '.../src/ProductList/ProductsData'`가 찍혀 있었습니다. 이 프로젝트는 `"type": "module"`(ES 모듈)이라, 실제 서버의 Node는 import 경로에 **확장자가 없으면 파일을 찾지 않습니다.** 브라우저 코드는 Vite가, 로컬 개발 서버는 개발 도구가 확장자를 알아서 찾아줘서 드러나지 않았습니다.
- 해결: 서버 함수가 불러오는 연결 고리(`api/confirm.ts` → `ProductsData` → `OptionsData`)의 import에 `.js` 확장자를 붙였습니다. 서버에는 `.ts`가 `.js`로 변환되어 올라가기 때문에 실행 시점의 이름인 `.js`로 적고, TypeScript와 Vite는 `.js`로 적어도 옆의 `.ts` 파일을 찾아 줍니다. **머지 전에 미리보기 배포로 확인한 덕분에** 실제 사이트에 나가기 전에 발견했습니다.
